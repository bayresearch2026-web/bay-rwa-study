고객자산 지갑

고객 자산 대신 보관

  • 돈의 주인 회사 아닌 고객
  • 회사 돈과 섞지 않고, 필요할 때 돌려줄 수 있어야함
역할
고객을 대신해 자산 보관 · 이전 · 매수 · 환매 처리
원칙
누구의 자산인지 분명히 기록하고 고객별 보유량 확인

핵심은 고객 자산을 섞이지 않도록 구분하고 안전하게 반환

보관 방식

고객마다 따로 보관 vs 한곳에 모아서 관리

01

고객별 개별 지갑

투명함, 고객마다 별도 블록체인 주소

  • 장부 일일이 안 뒤져봐도 누구 자산인지 한눈에 확인
  • 다만, 고객 늘수록 관리할 지갑도 그만큼 증가
02

통합 지갑

빠르고 효율적, 하나의 큰 지갑에 모으고 내부 장부로 구분

  • 자산 주고받을 때마다 매번 비싼 수수료 낼 필요 없음
  • 다만, 장부랑 실제 온체인 잔고 계속 검증 필요

중요한 건, 어떤 방식이든 전부 실제 잔고랑 일치해야 함

지켜야 할 것

01

회사 돈과 섞지 않기

청약·환매처럼 잠시 머무는 돈도 주인이 고객이면 고객자산으로 분리

02

수량 맞는지 수시로 확인

고객별 기록 백업하고 내부 장부와 실제 온체인 잔고를 계속 대조

03

회사 망하거나 서버 다운되도

다른 지갑·수탁기관으로 옮기거나 고객에게 반환할 절차 마련

04

누가 책임지는지 확인하기

벤더가 기술만 제공하는지, 실제 자산까지 맡는지 계약으로 구분 필요

기업자산 지갑

회사가 소유해서 운영하는 자금

같은 회사 자산이라도 쓰임새와 사고 범위에 따라 관리 방식이 달라짐

01

재무자산

예비자금처럼 오래 묶어두는 큰 돈

안전이 우선
02

운영자금

정산·수수료·가스비처럼 자주 쓰는 돈

빠른 처리가 우선
03

관리자 권한

발행·소각·동결 등 서비스 전체를 움직이는 권한

강한 통제가 우선

외부수탁형

전문기관에 맡김

특징

  • 키는 수탁기관이 보관하고 회사는 화면·API로 입출금을 요청
  • 거래가 적고 규모가 큰 예비자금 보관에 적합

장점

  • 보안 인프라 구축과 키 관리 부담을 전문기관에 위임
  • 회계 감사·규제 대응과 사고 시 보험 적용에 유리

단점

  • 출금 속도·지원 자산·컨트랙트 사용이 수탁기관 정책에 제한
  • 기관의 건전성과 도산 시 자산 반환 절차를 확인해야 함

직접수탁형

회사가 직접 관리

특징

  • 회사가 암호화 키와 최종 승인 권한을 직접 통제
  • 잦은 정산·자동 대금 지급 등 일상 운영자금에 적합

장점

  • 외부 기관의 승인 없이 자산을 빠르고 유연하게 운용
  • 다중 서명·복수 승인 등 회사에 맞는 결제 체계를 설계

단점

  • 키 분실·해킹으로 발생한 손실과 사고 대응은 회사의 책임
  • 보안 인프라 유지와 권한 회수 등 내부 통제 부담이 큼

마무리

새로 알게 된 용어

통합 지갑Omnibus Wallet
  • 여러 고객의 자산을 하나의 지갑에 보관
  • 고객별 잔액은 내부 장부로 구분
대사Reconciliation
  • 내부 장부와 실제 온체인 잔고를 비교
  • 차이가 없는지 계속 확인
벤더Vendor
  • 기술이나 시스템 솔루션을 기업에 제공하는 전문 업체
  • 지갑 기술 제공과 실제 자산의 수탁 책임은 별개

핵심 정리

01

기업자산 운영 지갑의 핵심은 누가 키를 통제하는지

02

외부수탁형은 관리 부담을 줄이는 대신 기관 정책과 위험을 확인

03

직접수탁형은 빠르고 유연하지만 보안과 사고 책임도 회사가 부담

04

준비금은 외부수탁형에, 일상 운영자금은 직접수탁형에 배치

05

운영자금이 부족할 때만 엄격한 내부 승인을 거쳐 필요한 만큼 리필
